# Materia ERP 物料管理系统 PRD

## 1. 项目背景与目标

### 1.1 项目背景
Materia ERP 面向 mRNA/LNP 生产场景，服务原辅料、脂质原料、中间体、成品、实验耗材、仪器设备等物料的全生命周期管理。当前团队规模较小，但物料种类多、批次要求严、效期敏感、追溯链条长，若仍依赖 Excel 或人工登记，容易出现批号缺失、库存不准、过期误用、追溯困难和审批留痕不足等问题。

MVP 阶段优先解决“能安全、可追溯地完成出入库与库存管理”这一核心问题，为后续扩展盘点、报表、设备管理和外部系统集成打基础。

### 1.2 项目目标
1. 建立统一的物料主数据与仓库数据管理机制。
2. 让所有入库、出库、盘点调整都走“提交—审批—执行”闭环。
3. 以“物料 + 批号 + 仓库”为最小库存单元，支持实时库存查询。
4. 支持从成品追溯到原料批次，也支持从原料批次追踪去向。
5. 通过 RBAC、审批和日志，满足小团队基础数据安全与审计需求。

### 1.3 成功标准
- 所有库存变更都来自审批通过的业务单据，不允许手工直接改库存。
- 出库操作 100% 拦截负库存。
- 批号字段在所有出入库场景中必填且可追溯。
- 过期物料不可出库，临期物料可预警。
- 10 人以内团队可在单机 Docker Compose 环境稳定运行。

## 2. 目标用户与角色定义

### 2.1 管理员（Administrator）
**职责**：维护基础数据与系统配置，保障系统正常运行。

**核心权限**：
- 物料主数据 CRUD
- 仓库管理
- 用户管理与角色分配
- 查看全部库存、审批、盘点、日志与报表
- 配置效期预警阈值、状态字典等系统参数

**限制**：
- 不应绕过审批流程直接制造库存变更

### 2.2 审核员（Reviewer）
**职责**：审核操作员发起的业务单据与盘点调整，控制库存变更生效。

**核心权限**：
- 审核入库单、出库单、盘点调整单
- 填写驳回理由
- 查看待审核列表与审核历史

**限制**：
- 不负责物料主数据维护
- 不可编辑已提交单据的业务内容，只能审核通过或驳回

### 2.3 操作员（Operator）
**职责**：发起入库、出库、盘点等日常业务操作。

**核心权限**：
- 新建入库申请、出库申请
- 发起盘点任务与填写盘点结果
- 查看与自己相关的单据、库存和操作记录

**限制**：
- 不可审批
- 不可修改物料主数据与系统设置

## 3. 业务规则摘要

1. **物料编码手动填写且系统唯一**。
2. **批号必填**，库存以“物料 + 批号 + 仓库”为最小管理单元。
3. **不允许负库存**，出库前必须校验可用库存。
4. **所有入库、出库、盘点调整均需一级审批后生效**。
5. **效期 ≤ 30 天预警，已过期物料自动锁定不可出库**。
6. **支持批次追溯**，从成品可逆向追溯到原料批次。
7. **库存变更必须可审计**，保留申请人、审核人、时间、理由与数量变化记录。

## 4. 功能需求

### 4.1 P0（必须有）

#### FR-P0-01 物料主数据管理
- 管理员可新增、编辑、停用、查询物料。
- 物料字段至少包括：物料编码、物料名称、物料类别、规格、单位、是否启用批次、是否启用效期、存储条件、备注。
- 物料编码必须唯一。
- 停用物料不可用于新单据，但历史数据可查看。

#### FR-P0-02 仓库管理
- 管理员可新增、编辑、停用仓库。
- 仓库需支持编码、名称、位置、状态等基础属性。
- 停用仓库不可用于新单据。

#### FR-P0-03 入库申请
- 操作员可发起采购入库、生产入库、退货入库。
- 必填字段：入库类型、物料编码、批号、数量、单位、仓库。
- 对启用效期的物料，需填写生产日期、有效期至。
- 提交后状态变为“待审核”。

#### FR-P0-04 入库审核与执行
- 审核员可查看待审核入库单并执行通过或驳回。
- 驳回时必须填写理由。
- 审批通过后系统自动增加对应库存余额。
- 库存增加应落到指定“物料 + 批号 + 仓库”维度。

#### FR-P0-05 出库申请
- 操作员可发起生产领料、报废出库、调拨出库。
- 必填字段：出库类型、物料编码、批号、数量、单位、仓库、用途/去向。
- 系统在提交时至少校验基础字段完整性。
- 提交后状态变为“待审核”。

#### FR-P0-06 出库审核与执行
- 审核员可查看待审核出库单并执行通过或驳回。
- 驳回时必须填写理由。
- 审批通过前，系统再次校验库存可用量与效期状态。
- 审批通过后系统自动扣减库存。
- 若库存不足或物料过期，系统拒绝执行并提示原因。

#### FR-P0-07 实时库存查询
- 用户可按物料编码、物料名称、批号、仓库、物料类别查询库存。
- 库存列表展示至少包括：可用数量、锁定状态、生产日期、有效期至、效期状态。
- 支持查看单一库存记录的历史收发明细。

#### FR-P0-08 三角色 RBAC 权限控制
- 用户登录后根据角色展示不同菜单与操作按钮。
- 操作员不可见审批按钮。
- 审核员不可编辑物料主数据。
- 管理员可查看全部数据并维护基础配置。

#### FR-P0-09 批次追溯
- 支持记录生产入库与生产领料之间的批次关联。
- 可从成品批号逆向查看消耗过的原料/中间体批号。
- 可从原料批号正向查看被哪些中间体或成品批次使用。
- 追溯结果至少展示：上游/下游物料、批号、数量、单据号、时间。

#### FR-P0-10 审批记录与操作留痕
- 所有入库单、出库单必须保存申请人、申请时间、审核人、审核时间、审核结果、驳回理由。
- 所有库存变更需可回溯到来源单据。

### 4.2 P1（尽快有）

#### FR-P1-01 效期预警与过期锁定
- 临期物料（≤30 天）在列表、详情、审批界面高亮提醒。
- 过期物料自动锁定，不允许出库。
- 支持管理员查看临期/过期清单。

#### FR-P1-02 库存盘点
- 操作员可发起盘点任务，按仓库或物料范围录入实盘数量。
- 系统自动生成盘盈/盘亏差异。
- 盘点调整需审核员审批后才写入库存。

#### FR-P1-03 审计日志
- 记录登录、主数据修改、审批动作、库存调整等关键事件。
- 支持按时间、用户、对象类型查询。

### 4.3 P2（后续迭代）

#### FR-P2-01 报表中心
- 库存日报
- 收发存月报
- 呆滞料分析

#### FR-P2-02 仪器设备台账与校准管理
- 记录设备信息、状态、校准周期与到期提醒。

#### FR-P2-03 增强型仓储能力
- 多仓库调拨闭环
- 更细粒度库位管理

#### FR-P2-04 外部系统集成
- 与 LIMS、QMS 等系统对接

## 5. 非功能需求

### 5.1 性能
- 10 人以内团队并发使用时，常规查询与提交流程响应时间目标 ≤ 3 秒。
- 常规库存查询列表支持分页，避免一次性加载全部记录。
- 审批通过时库存扣减/增加必须在事务内完成，确保一致性。

### 5.2 安全
- 系统必须提供基本身份认证。
- 基于角色进行接口与页面访问控制。
- 库存变更相关接口必须记录操作日志。
- 敏感配置（数据库密码、密钥等）必须通过环境变量管理。

### 5.3 可用性
- 页面必须具备 Loading / Error / Empty 三态。
- 关键表单字段提供明确校验提示。
- 审批失败、库存不足、过期锁定等错误应给出可理解的业务提示。
- Docker Compose 部署文档应可支持单机快速启动。

### 5.4 数据一致性
- 出入库、盘点调整必须通过数据库事务保证原子性。
- 出库执行前必须锁定库存记录并再次校验可用数量。
- 数量字段使用定点数，禁止浮点数造成精度误差。

### 5.5 可审计性
- 库存变化必须能追溯到业务单据与审批记录。
- 主数据与权限变更需要保留操作者和时间戳。

## 7. 系统边界（MVP 不做什么）

### 7.1 本期不做
- 自动生成复杂物料编码规则
- 财务成本核算与采购付款管理
- 完整的生产工单/MES 管理
- 高级报表中心
- 设备校准与维修闭环
- 与 LIMS/QMS/ERP 等外部系统的正式接口集成
- 多组织、多工厂、多租户能力
- 条码/扫码枪/移动端专项适配

### 7.2 本期原则
- 先保证物料、库存、审批、追溯闭环可用。
- 不追求一次性覆盖生产全链条，只覆盖最核心的仓储与物料流转场景。

---

## 8. 关键业务约束

1. 批号不可为空。
2. 数量精度建议使用 NUMERIC(18,6)。
3. 金额如后续涉及，使用 NUMERIC(18,4)。
4. Controller 不承载业务逻辑，业务规则落在 Service 层。
5. 所有 API 入参需做参数校验。
6. 库存变更需通过审批驱动，不允许绕过审批直接写库存。

## 10. 验收原则

P0 验收以“真实业务闭环可跑通”为标准：
1. 管理员可维护物料与仓库。
2. 操作员可发起入库和出库申请。
3. 审核员可审批并驱动库存变更。
4. 系统可实时查看库存。
5. 系统可从成品批次追溯到原料批次。
6. 非授权角色无法执行越权操作。
